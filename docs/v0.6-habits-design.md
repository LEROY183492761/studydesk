# 习惯管理优化设计（v0.6）

## 1. 适用场景

| 场景 | 典型习惯 | 推荐配置 |
|---|---|---|
| 计数型目标 | 每天 20 个俯卧撑、今天背 100 个单词 | 单位「个/次」，每日目标量 20 / 100 |
| 累积型目标 | 某日期前累计跑步 100 次、读完 1000 页 | 绑定目标 + 目标总量，习惯每日目标量可选 |
| 任务型打卡 | 每天 3 组拉伸、每天 2 次冥想 | 模式「任务化」，每日目标量 = 任务量 |
| 时间型打卡 | 每天阅读 30 分钟、每天练琴 1 小时 | 单位「分钟/小时」，系统按计时自动累计 |

适合：需要记录「一次做了多少」而不是仅记录「今天做没做」的用户。
不适合：只需要二元打卡（今天完成/未完成）的极简场景——仍可用默认单位「次」、每日目标量 1。

## 2. 数据字段

### Habit 新增

| 字段 | 类型 | 说明 |
|---|---|---|
| `unit` | `string` | 打卡单位，默认「次」；预置 次/个/页/公里/米/分钟/小时 |
| `dailyTarget` | `number` | 每日目标量，也是环比的分母；默认 1 |
| `unitMinutes` | `number?` | 每单位折算分钟（如 1 页 = 2 分钟），用于写时间轴 |
| `goalId` | `string?` | 绑定的目标 id |
| `timerMinutes` | `number?` | 保留字段；任务化模式不再要求用户填写 |

### HabitLog 新增

| 字段 | 类型 | 说明 |
|---|---|---|
| `unit` | `string?` | 本次打卡单位快照（历史记录按原单位保留） |
| `recordedAt` | `string?` | 本次打卡时刻（ISO）；同一天多次打卡各有一条 |
| `minutes` | `number?` | 本次折算分钟，写时间轴时使用 |
| `value` | `number` | 本次完成量（原字段，含义由「1 次」扩展为「本次数量」） |

### Goal 新增

| 字段 | 类型 | 说明 |
|---|---|---|
| `habitId` | `string?` | 绑定习惯 |
| `targetAmount` | `number?` | 目标总量（周期内累计） |
| `autoProgress` | `boolean?` | 为 true 时进度由习惯累计自动计算 |

## 3. 计算规则

### 3.1 当日与周期累计

```text
当日累计量 = Σ 当日该习惯所有 log 的 value（按当前单位换算后）
周期累计量 = Σ 周期内该习惯所有 log 的 value（按当前单位换算后）
```

- 同一天允许多条 log，不去重、不合并；
- 打卡记录保留当时的 `unit`；统计时按「当前单位」换算；
- 同组单位可换算：秒/分钟/小时、米/公里；其他单位只在同名单位间累加；
- 无法换算的历史记录不强行相加，卡片显示「另有 N 条其他单位记录」。

### 3.2 环比（进度指标）

**分子在前，分母在后：**

| 类型 | 分子 | 分母 | 展示 |
|---|---|---|---|
| 目标型 | 当日/周期实际完成量 | 目标量（`dailyTarget` 或 `goal.targetAmount`） | `已完成 / 目标`，封顶 100% |
| 任务型 | 今日已打卡任务量（Σ value） | 今日累计任务量（`dailyTarget`） | `已打卡 / 今日任务量`，封顶 100% |

- 比例 = `min(1, 分子 / 分母)`；分母 ≤ 0 时比例记 0；
- 目标达成后继续打卡：累计量继续增长，比例保持 100%；
- 目标绑定习惯时，目标进度用「周期累计量 / `targetAmount`」，而不是手填 `progress`。

### 3.3 时间单位自动计算

- 单位属于时间组（分钟/小时）时，用户不输入数量，改由「开始任务 → 结束」记录；
- 本次 `value` = 计时秒数换算到习惯单位（分钟或小时）；
- `minutes` = 实际计时分钟，写入时间轴；
- 单位不是时间时，用户必须输入本次数量，任务型也按输入数量累计。

### 3.4 单位切换

- 切换只影响后续打卡，历史 log 不改写；
- 同组切换（分钟 ↔ 小时）时，输入框默认值按比例换算；
- 跨组切换（次 ↔ 页）时提示「历史数据将按原单位保留」，统计只累加当前单位；
- 卡片「单位」以习惯当前单位为准。

## 4. 关键交互

### 4.1 新增 / 编辑入口

- 页面顶部改为「+ 添加习惯」按钮；
- 点击后展开同一面板，面板同时承担新增与编辑；
- 编辑卡片时回填字段，按钮显示「保存修改」与「取消编辑」；
- 点击「添加习惯」或编辑其他习惯时，面板自动切换到对应模式。

### 4.2 打卡

- 轻量模式：数量输入（默认 1）+ 单位选择 + 「打卡」按钮；
- 任务化模式：`开始任务` → 实时显示计时 → `结束并记录`，系统按设备时间自动计算时长；
- 同一天可连续打卡多次，卡片显示「今日 N 次 · 累计 X 单位」；
- 每条打卡记录可单独删除（卡片内展示最近记录）。

### 4.3 卡片指标

- 标题下方显示频率、模式、单位、提醒；
- 环比区显示 `分子/分母 + 百分比` 与进度条；
- 7 天格子显示每日累计量（有记录显示数量，无记录显示日期）；
- 目标型显示「完成量 / 目标量」，任务型显示「已打卡 / 今日任务量」。

## 5. 异常与边界

| 情况 | 处理 |
|---|---|
| 同一天多次打卡 | 每条独立 log，累计相加，不去重 |
| 输入 0 / 负数 | 拒绝打卡，提示「完成量需大于 0」 |
| 输入超大值 | 上限 999999，避免误输入撑爆统计 |
| 单位无法换算 | 历史记录保留原单位，统计跳过该条并提示 |
| 计时为 0 秒 | 按 1 分钟计，避免 0 时长记录 |
| 跨天计时 | 以结束时刻所在日期归集，`recordedAt` 留完整时间 |
| 目标达成后继续打卡 | 允许，比例封顶 100%，累计量继续增长 |
| 删除绑定习惯 | 目标保留，自动进度失效并回退到手动 `progress` |
| 目标量为 0 或未填 | 按 1 处理，避免除零 |
| 历史习惯无 unit | 视为「次」，`dailyTarget` 视为 1，行为与旧版一致 |

## 6. 方案优缺点

**优点**

- 一次打卡可记录数量，适合跑步、背单词、俯卧撑等可量化习惯；
- 单位与目标量解耦，同一习惯可切换统计口径；
- 目标与习惯绑定后进度自动累计，减少手工维护；
- 任务型不再要求手动填写时长，降低配置成本；
- 历史记录保留原始单位，避免换算丢失信息。

**缺点 / 代价**

- 单位跨组不可换算，统计口径需要用户理解；
- 同一天多条记录会增加列表数据量，需要单条删除与管理入口；
- 绑定目标后进度依赖习惯记录，删除习惯会使目标退回手动进度；
- 任务型自动计时依赖平台计时器，应用重启时可能丢失进行中的计时（已有约束）。

## 7. 兼容与迁移

- 全部新增字段为可选，写入现有 `payload` JSON，**schema 仍为 v7，无需迁移**；
- 旧习惯：`unit` 缺省「次」、`dailyTarget` 缺省 1，打卡行为与旧版一致；
- 旧 log：`unit` 缺省「次」、`value` 即完成量，累计规则可直接兼容；
- 旧目标：无 `habitId` / `targetAmount` 时继续使用手填 `progress`。
