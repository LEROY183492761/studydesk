## 2. SQLite 关系表

### 2.1 表结构

```sql
schema_migrations(version PRIMARY KEY, applied_at)

kv_store(key PRIMARY KEY, value, updated_at)

tasks(id PRIMARY KEY, title, status, priority, source,
      due_at, scheduled_start, scheduled_end, estimate_minutes,
      completed_at, created_at, updated_at, payload)

events(id PRIMARY KEY, title, start_at, end_at, all_day,
       category, location, source, payload)

focus_sessions(id PRIMARY KEY, task_id, started_at,
               planned_seconds, actual_seconds, mode,
               completed, note, payload)

notes(id PRIMARY KEY, content, created_at, updated_at, payload)
```

设计要点：

- **查询列 + payload**：常用字段（状态、开始时间、类型）冗余成列并建索引，完整对象存 `payload`，避免字段遗漏与频繁迁移；
- **索引**：`idx_tasks_status`、`idx_tasks_scheduled`、`idx_events_start`、`idx_focus_started`；
- **WAL**：读写并发更稳；
- **数据库位置**：`%APPDATA%\com.studydesk.app\studydesk.db`。

### 2.2 迁移

`db::migrate_kv` 在启动时执行：

1. 检查 `schema_migrations` 是否已有 version 2；
2. 未迁移时，在事务中读取 KV 中的 `studydesk.v1.tasks / events / focus / notes`；
3. 逐条写入对应关系表（`INSERT ... ON CONFLICT DO UPDATE`）；
4. 记录 version 2，提交事务。

迁移保留 KV 数据作为回滚备份，不删除。

## 3. 前端仓储切换

`PlatformPort` 新增 `DatabasePort`：

```ts
interface EntityStore {
  list(): Promise<unknown[]>;
  save(item: unknown): Promise<void>;
  remove(id: string): Promise<void>;
  clear(): Promise<void>;
}

interface DatabasePort {
  tasks: EntityStore;
  events: EntityStore;
  focusSessions: EntityStore;
  notes: EntityStore;
}
```

- **Tauri**：调用 `task_list/task_save/...`、`event_*`、`focus_session_*`、`note_*` 共 16 个命令；
- **Web**：用 localStorage 上的等价集合实现，键与旧 KV 一致，Web 端数据不丢。

`createRepositoryBundle(platform)` 中：

- `tasks / events / focus / notes` 走 `platform.database`；
- `settings / timetable / 复习卡片 / 记账 / 快捷录入` 仍走 `platform.storage`（KV）。

### 种子初始化

- 使用 KV 标记 `studydesk.v1.seeded`；
- 首次启动且四类实体都为空时写入种子（4 任务 / 3 日程 / 2 专注 / 1 随想），并标记 seeded；
- 用户清空数据后不会重复灌入种子；
- 「重置演示数据」会清空关系表与 KV，再重新写入种子。

## 4. Rust 侧番茄时钟

`FocusRuntime` 用 `Mutex<FocusInner>` 保存状态，计时基于 `std::time::Instant`：

| 命令 | 作用 |
|---|---|
| `focus_start` | 重置并开始，记录开始时间戳 |
| `focus_pause` | 累计已用时长并暂停 |
| `focus_resume` | 恢复计时 |
| `focus_status` | 返回当前快照（前端 500ms 轮询） |
| `focus_stop` | 结束并返回实际秒数、开始时间、是否完成 |

前端 `FocusTimerPort` 双实现：桌面端走 Rust 命令，Web 端用 `Date.now()` 等价实现。FocusPage 不再自己维护倒计时。

## 5. 排期冲突提示与拖拽

- 待办排期时：`applySchedule` → `buildCalendarItems` → `scheduleConflicts`，保存后提示“与「X」时间重叠”；
- 日历侧栏“待排期”列表可拖到日/周时间格，按落点垂直位置换算时间（15 分钟对齐），默认 60 分钟。

## 7. 当前限制

- 拖拽仅支持日/周视图，月视图未支持。
- 冲突提示不阻断保存。
- 关系表尚未支持跨实体事务与增量同步；`change_log` 仍为后续规划。
- Web 端仍使用 localStorage，与桌面端 SQLite 行为等价但引擎不同。
- 番茄计时未接系统通知（结束提醒仍靠页面）。
