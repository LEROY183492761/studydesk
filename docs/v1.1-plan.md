# v1.1 功能预留与增量接入方案

v1.1 计划加入四项功能：间隔重复卡片、全局快捷录入、悬浮窗、轻量记账。
M0 已在模型、仓储、平台端口、注册表与开关五个层面预留接入点，以下为边界、依赖与接入步骤。

## 1. 模块边界

| 功能 | 前端模块 | 领域模型 | 仓储接口 | 平台能力 | 默认开关 |
|---|---|---|---|---|---|
| 间隔重复卡片 | `features/lab/review-cards/` | `ReviewCard` / `ReviewLog` | `ReviewCardRepository` / `ReviewLogRepository` | 无 | `flags.reviewCards` |
| 全局快捷录入 | `features/lab/quick-capture/` | `CaptureDraft` / `CaptureRecord` | `CaptureRepository` | `shortcuts` / `clipboard` | `flags.quickCapture` |
| 悬浮窗 | `features/lab/floating-window/` | `FloatingWindowState` | 无（只读状态） | `windowControl` | `flags.floatingWindow` |
| 轻量记账 | `features/lab/ledger/` | `LedgerEntry` / `LedgerCategory` / `LedgerBudget` | `LedgerRepository` | 无 | `flags.ledger` |

模块目录内已放置 `manifest.tsx`，通过注册表接入路由与导航；开关关闭时入口不可见，但路由仍可直达占位页，便于开发调试。

## 2. 相互依赖关系

```
                    ┌──────────────────┐
                    │  quick-capture   │
                    │  解析 + 分发      │
                    └───┬────┬────┬────┘
                        │    │    │
              ┌─────────┘    │    └──────────┐
              ▼              ▼               ▼
        ┌──────────┐   ┌──────────┐   ┌──────────┐
        │  tasks   │   │  notes   │   │  ledger  │
        └──────────┘   └────┬─────┘   └────┬─────┘
                            │              │
                            ▼              ▼
                     ┌────────────┐  ┌────────────┐
                     │review-cards│  │ today 组件 │
                     └─────┬──────┘  └────────────┘
                           ▼
                     ┌────────────┐
                     │   review   │
                     └────────────┘

        floating-window ──只读──> focus + timetable
```

依赖原则：
- 快捷录入是“入口”，只依赖下游模块的公开动作，不反向被依赖。
- 复习卡片依赖随想与课程作为卡片来源，并向今日/复盘输出队列与指标。
- 悬浮窗是纯消费方，不产生业务数据。
- 记账与复习卡片互不依赖；记账通过今日页挂件露出，不写入日历模型。

## 3. 数据模型预留（已落地）

| 模型 | 关键字段 | 设计说明 |
|---|---|---|
| `ReviewCard` | `front/back/tags/easeFactor/intervalDays/dueAt/lapses` | SM-2 简化版所需字段齐全，M0 不实现调度 |
| `ReviewLog` | `cardId/rating/elapsedMs` | 评分四档（again/hard/good/easy），支持后续统计 |
| `CaptureDraft` | `kind/title/dueAt/amountCents/...` | 统一解析结果，按 `kind` 分发到四个模块 |
| `CaptureRecord` | `rawText/draft/appliedTo` | 保留原文与落地结果，支持回溯与纠错 |
| `LedgerEntry` | `amountCents/kind/categoryId/occurredAt/source` | 金额以“分”存储，避免浮点误差 |
| `LedgerBudget` | `month/amountCents` | 按月预算，不做复式记账 |
| `FloatingWindowState` | `visible/alwaysOnTop/mode/opacity` | 窗口状态与业务状态分离 |

表结构变更只新增、不修改既有表；M1 建立 SQLite 迁移基线，v1.1 以 `migration v2` 增加四组表。

## 4. 接口占位（已落地）

- `data/repositories/types.ts`：`ReviewCardRepository`、`ReviewLogRepository`、`LedgerRepository`、`CaptureRepository`。
- `data/repositories/local.ts`：上述接口的 localStorage 实现已可运行，M0 只未接 UI。
- `features/lab/quick-capture/parser.ts`：`NaturalLanguageParser` 契约与规则解析器最小实现。
- `platform/types.ts`：`shortcuts`、`windowControl`、`clipboard` 三个 v1.1 直接依赖的端口。
- `src-tauri/src/lib.rs`：`shortcut_register`、`floating_set_*`、`secret_*` 命令占位，保证前端调用不因缺命令而崩溃。
- `AppSettings.flags`：四个开关已加入默认设置并持久化。

## 5. 兼容性评估

| 维度 | 影响 | 兼容性 |
|---|---|---|
| 领域模型 | 新增 `domain/models/v11.ts`，不改 `CalendarItem`、`Task` | 完全兼容 |
| 数据层 | 新增表与仓储方法；既有仓储签名不变 | 兼容，需迁移脚本 v2 |
| 路由与导航 | 注册表新增条目，flag 控制可见性 | 完全兼容 |
| 状态管理 | 建议新增 `ledgerStore`、`reviewStore`，不塞入 `appStore` | 兼容，需一次小重构 |
| 构建依赖 | 四项功能均无需新增 npm 依赖 | 兼容 |
| 桌面端 | 悬浮窗需要新增第二个 Tauri 窗口定义与窗口间事件 | 需配置变更，不影响主窗口 |
| 性能 | 复习队列与今日聚合增加计算量 | 可接受；卡片量大时分页查询 |
| 隐私 | 记账与卡片属于 L1 个人数据；仍只存本地 | 符合现有分级 |

**主要风险**
1. `appStore` 膨胀：v1.1 前先按域拆 slice，否则单文件会超过可维护阈值。
2. localStorage 容量与并发写：卡片与账目增多后必须迁移 SQLite。
3. Tauri 多窗口通信：悬浮窗与主窗口的状态同步需要明确事件契约，避免双向写冲突。
4. 快捷录入解析歧义：规则解析器必须保留 `CaptureRecord.rawText`，允许用户确认后再落地。

## 6. 增量接入方案（按功能）

### 6.1 间隔重复卡片

1. 在 `features/lab/review-cards/` 内实现卡片列表、编辑与今日复习队列。
2. 在 `domain/rules/` 新增 `srs.ts`：SM-2 简化调度（again/hard/good/easy → interval/ease）。
3. 今日页通过 `widgets` 贡献点挂载“待复习 N 张”，不修改 `TodayPage` 主体。
4. `review.card.graded` 事件接入复盘指标（新增 `cardsReviewed` 字段，向后兼容）。
5. 开关默认改为 `true`，补迁移与单测。

### 6.2 全局快捷录入

1. 在 `platform` 层注册 `Ctrl+Alt+N`，Tauri 侧接通 `shortcut_register`；Web 端回退到页面内 `Ctrl+K`。
2. 新增录入浮层，调用 `ruleBasedParser`；后续可叠加 AI 解析器（同一 `NaturalLanguageParser` 接口）。
3. 分发器按 `CaptureDraft.kind` 调用 `addTask` / `addNote` / `saveEntry` / 新建日程。
4. 写入 `CaptureRecord`，记录 `appliedTo`，失败时保留草稿供重试。
5. 开关默认改为 `true`，补快捷键冲突处理与单测。

### 6.3 悬浮窗

1. `tauri.conf.json` 增加第二个窗口（`label: "floating"`，`alwaysOnTop`、无边框、透明）。
2. Rust 侧实现 `floating_set_visible` / `floating_set_always_on_top`，并广播专注与课表状态。
3. 前端新增 `features/lab/floating-window/FloatingWindow.tsx`，只读订阅 `focus` 与 `timetable`。
4. 与主窗口通过事件契约同步，禁止悬浮窗直接写业务数据。
5. 开关默认改为 `true`；未安装 Tauri 时 Web 端显示不可用提示。

### 6.4 轻量记账

1. 实现 `LedgerPage`：录入、分类、月度汇总、预算进度。
2. 今日页新增挂件：今日支出、本月预算余量（通过 `widgets` 贡献点）。
3. `quick-capture` 的 `ledger` 草稿接入 `saveEntry`。
4. 月度报表复用 `domain/selectors`，不引入图表库，先用 CSS 条形图。
5. 开关默认改为 `true`，补金额精度与边界测试。

## 7. v1.1 验收标准

| 功能 | 验收标准 |
|---|---|
| 间隔重复卡片 | 可从随想生成卡片；评分后到期日按规则推进；今日队列与复盘指标可对账 |
| 全局快捷录入 | 快捷键可唤起；一句话可生成待办/随想/记账；失败保留原文；Web 端有降级 |
| 悬浮窗 | 置顶显示倒计时与下一节课；主窗口状态变化 1 秒内同步；关闭后不残留窗口 |
| 轻量记账 | 新增/删除账目；月度分类汇总准确到分；今日挂件与明细一致 |
| 兼容性 | 关闭四个开关时，应用行为与 M0 完全一致；旧数据可读 |
| 回归 | 既有领域测试全部通过，新增四项功能各有单测 |
