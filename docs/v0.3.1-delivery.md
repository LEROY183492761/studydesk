## 2. 四象限

### 2.1 维度

- **重要性**：`Task.importance` 手动设置；未设置时由 `priority` 推导（`urgent/high → 高`）。
- **紧急性**：`isUrgent` 按截止时间自动推导，截止 ≤48 小时或已逾期即紧急。
- 映射：`high + urgent → Q1`、`high + 不紧急 → Q2`、`low + 紧急 → Q3`、其余 `Q4`。

### 2.2 交互

- 待办页顶部切换「列表 / 四象限」。
- 四象限为 2×2 卡片，每格显示数量与建议（马上处理 / 优先投入 / 尽量委托 / 减少投入）。
- 拖拽任务到另一象限：只改写 `importance`；若目标象限的紧急维度与当前不同，保存后提示「紧急性由截止时间决定」。
- 每格「+ 新建」会把输入框切到该象限，提交时预填重要性。

## 3. DDL 双向同步

### 3.1 创建

日程页新建时选择类型：

- **日程**：起始时间 + （结束时间 | 持续时间）。
- **DDL**：标题 + 截止日期时间 + 地点。

创建 DDL 时通过 `buildDeadlinePair` 一次生成：

- `ScheduleEvent { kind: 'deadline', start = end = 截止时间, linkedTaskId }`
- `Task { source: 'deadline', dueAt, linkedEventId, status: 'inbox', priority: 'high' }`

### 3.2 显示与删除

- 日历详情中 DDL 显示为「DDL」标签；关联待办完成后显示「已完成」，时间块加删除线与降低透明度。
- 删除 DDL 时，若存在关联待办，弹窗询问「是否同时删除」。
- 删除待办时，若存在关联 DDL，弹窗询问「是否同时删除」。

### 3.3 未完成项

- 「修改 DDL 时间/标题后双向更新」的**编辑入口**本轮未做（日历暂未提供编辑功能）；数据模型与关联字段已就绪，计划在 v0.3.2 随循环日程编辑一起实现。
- 双写不是跨实体事务；两个 `save` 之间若异常可能出现单边数据，已记入 backlog。

## 4. 日程时间输入

- 新增「时长 / 结束」切换：
  - 时长：开始时间 + 15/30/45/60/90/120 分钟。
  - 结束：开始时间 + 结束时间，自动计算时长。
- 结束早于开始（时长 <5 分钟）时提示「结束时间需晚于开始时间」，不保存。

## 5. 数据库 v5

```sql
events 新增：kind TEXT NOT NULL DEFAULT 'event',
             repeat_json TEXT,
             exdates_json TEXT,
             linked_task_id TEXT
CREATE INDEX idx_events_kind ON events(kind);
```

迁移 `migrate_v5`：

- 在事务中按列存在性执行 `ALTER TABLE`；
- **索引创建放在 ALTER 之后**，否则旧库启动时会在 `init_schema` 阶段报 `no such column: kind`（实际踩过并修复）；
- 记录版本 5，幂等。
